# 保管場所のチャット経由登録 手順書

利用者がチャットで伝えた「物と場所」を、AI（Claude・Codex など、どれでもよい）や人が
**アプリの API 経由で**まとめて登録するための手順。特定の AI 専用の仕組みではなく、
この手順とリポジトリ内の CLI（`npm run storage`）だけで誰でも同じ結果になるようにしている。

- 登録は **production の API を利用者のアカウントで呼ぶ通常のアプリ操作**であり、deploy や DB 直接操作ではない。
  VPS 管理の承認は不要。ただし **利用者が確認表を見て OK するまで本登録しない**（下記 3）。
- DB を直接書き換えない（production DB の write は別の厳格な例外手順の対象）。
- 前提: API に保管場所機能（notice `20261020-STOCKHOME-022`）が本番反映済みであること。

## 1. 準備（実行する PC ごとに1回）

`apps/api/.env.local`（gitignore 対象。コミットしない）に次を書く。

```dotenv
STORAGE_CLI_API_URL=https://<API のホスト>   # 末尾の /api は不要
STORAGE_CLI_EMAIL=<利用者のログインメール>
STORAGE_CLI_PASSWORD=<利用者のパスワード>
```

- 認証情報をチャット・コード・Git・ログに書かない。
- ログイン後のトークンは `apps/api/.data/storage-cli-token.json`（gitignore 対象）に保存され、
  有効な間（90日）は再ログインしない。ログイン API にはアカウント別の回数制限（15分に5回）がある。
- 実行環境が外部へ HTTPS 通信できること（AI のサンドボックスでネットワークが塞がれている場合は実行できない。
  その場合は登録用 JSON を作るところまでにして、実行は人か通信できる環境へ渡す）。

## 2. 登録内容を組み立てる

まず現在の登録状況を見る。**既存の場所名・用途タグ名に合わせる**ことが最重要（表記ゆれを作らない）。

```powershell
npm run storage -- lookup              # 場所の木・用途タグ（使用数）・消耗品名
npm run storage -- search <キーワード>   # 名前・タグ・場所・メモで検索
```

利用者の話や写真から、次の形式の JSON を作る。**家の写真や JSON はリポジトリに置かない**
（AI の scratchpad など、リポジトリ外の一時領域を使う）。

```json
{
  "entries": [
    {
      "kind": "thing",
      "name": "ほうき",
      "memo": "柄が伸びるタイプ",
      "locations": [{ "path": ["1階", "パントリー", "A棚", "1段目"], "memo": "床置き" }],
      "tags": ["掃除全般"]
    },
    {
      "kind": "item",
      "name": "サンポール",
      "locations": [{ "path": ["1階", "トイレ", "収納棚"], "memo": "ストック" }],
      "tags": ["トイレ掃除"]
    }
  ]
}
```

| 項目 | 意味 |
|---|---|
| `kind` | `thing`＝場所だけ管理する物（同名の物があれば追記、無ければ新規）／`item`＝既存の消耗品へ場所・タグを追加（消耗品の新規作成はしない） |
| `name` | 物の名前、または消耗品の品名（`lookup` の表記と完全一致。同名が複数なら `itemId` で指定） |
| `memo` | 物自体のメモ（`thing` のみ。指定したときだけ上書き） |
| `locations[].path` | 最上位からの場所名の並び。無い階層は自動で作られる（最大8段） |
| `locations[].memo` | その場所での置き方（「右奥の青いケース」「ストック2個」など） |
| `tags` | 用途タグ（追加のみ。既存のタグは外さない） |

組み立ての目安:

- 階層は「家族が呼び分けている単位」まで（例: 1階 › パントリー › A棚 › 3段目）。それより細かい位置は置き場所メモへ。
- 箱・ケースも場所として扱ってよい（例: …› Aクローゼット › 青いケース）。
- 写真から物の名前を読み取ったときは、推測した名前であることを確認表で利用者に伝える。
- 用途タグは利用者の言い方を優先しつつ、既存タグがあればそれに寄せる（「服汚れ」ではなく既存の「服の汚れ」）。

全角・半角や空白のゆれ（「Ａ棚」と「A棚」）は API 側で同じ名前として扱う。

## 3. 確認してから登録する（必須）

```powershell
npm run storage -- import <file.json>           # 確認（dry run。何も書き込まない）
npm run storage -- import <file.json> --apply   # 本登録
```

1. まず dry run を実行し、出力の表（新規／追記、追加する置き場所、新しく作る場所、🆕の新しいタグ）を
   **そのまま利用者に見せる**。
2. 利用者が OK したら `--apply` で本登録する。直す点があれば JSON を直して dry run からやり直す。
3. 1件でもエラーがあれば何も登録されない（全件取り消し）。エラーの行を直してやり直す。
4. 同じ JSON を2回登録しても重複は作られない（既存の場所・物・置き場所・タグを再利用する）。
5. 結果（件数と、新しく作った場所・タグ）を利用者に報告する。

dry run も本登録と同じ処理をトランザクション内で実行してから取り消すため、確認表と実際の登録結果は一致する。

## 4. 登録後の修正

一括登録は「追加」専用。名前の変更・場所の移動や統合・置き場所の削除・タグの統合は、アプリの画面
（段階4で追加予定）か、API（`/api/storage/*`、`apps/api/src/routes/storage.ts`）で行う。
